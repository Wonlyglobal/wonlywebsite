# CMS 版本差异与安全回滚 PRD

## 目标

在保留不可变历史和正式内容的前提下，将任意历史修订恢复成新的草稿，供再次预览、审批和发布。

## 规则

- 所有修订保留，恢复不会覆盖或删除历史记录。
- 恢复必须提交页面当前 `content_version`，并发改动时返回 `version_conflict`。
- 英文、翻译草稿和包含完整翻译快照的历史格式均可恢复。
- 恢复后页面版本加一，状态回到草稿，旧审批与待发布排期失效。
- 正式 `published_content` 不变；只有后续重新审批和发布才改变官网。
- 仅内容编辑与超级管理员可以恢复，操作写入修订和审计日志。

## 验收流程

1. 选择历史版本后显示与上一版本的字段级差异。
2. 只读、SEO、翻译、销售和审核发布角色不能执行恢复。
3. 内容编辑确认恢复后生成更高版本的新草稿，正式内容保持不变。
4. 历史快照为 `{locale, content}`、普通内容对象、或含 `translations` 的完整对象时均正确恢复。
5. 恢复后旧审批变为 `superseded`，待发布排期变为 `cancelled`。
6. 使用过期页面版本执行恢复返回 `version_conflict`，不会产生部分写入。
7. 修订表新增 `restored` 记录，审计表新增 `revision_restored` 记录并包含来源修订ID。

数据库迁移与生产浏览器回归完成前不得标记上线。

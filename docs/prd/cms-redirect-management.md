# 重定向管理 PRD 与验收

## 目标

用结构化、可审计的重定向规则替代自由 JSON。编辑者/SEO 保存草稿，审核发布角色启用或停用；不把 CMS 保存等同于生产网关已经生效。

## 数据与安全

- `cms_redirect_rules` 保存来源、目标、301/302、草稿/启用/停用、版本、操作者和命中数。
- 来源必须是无查询参数/锚点的站内路径；目标只接受站内路径或 HTTPS。
- 禁止自跳转、直接两节点循环、重复来源；更新采用乐观锁。
- 保存草稿需编辑或 SEO 权限；启停需发布权限；全部写入审计日志。
- `cms_active_redirects` 只公开启用规则，供官网运行时或生产网关同步器只读。

## 验收流程

1. Editor/SEO 新增规则，确认状态为 draft、公开网站不跳转。
2. Reviewer 启用后，确认公开视图仅出现 active 规则。
3. 生产网关同步后，用 `curl -I` 验证真实 301/302、Location 与查询参数策略；未同步前不得写“线上生效”。
4. 测试同源同目标、自跳转、A→B+B→A、非法 URL、旧版本并发更新，均应拒绝。
5. 编辑 active 规则后应回到 draft，旧线上规则需由同步器按发布快照处理。
6. 检查启用/停用/保存审计记录，Viewer 只能查看。

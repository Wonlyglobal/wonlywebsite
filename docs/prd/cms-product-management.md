# 产品数据管理 PRD 与验收

## 目标

以产品键和 SKU 为唯一主数据，集中管理型号、系列、官网路径、主图、简介、亮点、应用、规格和 FAQ；产品草稿经提交和异人发布后才进入官网公开接口。

## 数据与权限

- `cms_products` 保存唯一 product_key/SKU/route、系列、草稿、正式数据、翻译、版本和发布责任人。
- 路径必须属于 `/products/`，主图必须为站内绝对路径；标题、描述和主要数组做结构校验。
- Editor 编辑，Editor/SEO/Translator 可提交，Reviewer 异人发布；并发保存使用版本锁。
- `cms_published_products` 只公开正式快照。官网详情组件优先读取对应正式主数据，读取失败时回退代码内已验证目录数据。
- 保存草稿、提交和发布均写审计；不得用后台未发布数据覆盖官网。

## 验收流程

1. 导入现有型号并核对 product_key、SKU、系列、路由、图片和规格与官网一致。
2. 测试重复 SKU/route、非法产品键、站外主图、缺标题/型号、错误数组，确认拒绝。
3. 保存草稿后官网不变；提交后原编辑者不得发布，另一 Reviewer 发布后公开视图更新。
4. CatalogProductDetail 读取发布数据并验证 SEO、JSON-LD、主图、亮点、规格、FAQ 与报价产品上下文一致。
5. Supabase 不可用时官网回退内置目录且不白屏。
6. 桌面和390px检查列表、编辑器及产品详情；多语言无溢出，未发布译文不显示。

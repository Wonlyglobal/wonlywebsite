# CMS 自动保存与版本差异 PRD 与验收

## 目标

编辑页面时自动保存可恢复草稿，并以乐观锁阻止两个编辑者互相覆盖；版本历史支持字段级差异查看，任何历史恢复只生成新草稿，不直接修改正式网站。

## 数据与交互

- `cms_pages.content_version` 是当前草稿版本；保存必须提交 `expected_version`。
- `cms_revisions` 保存每次人工、自动保存和恢复产生的完整快照、版本号、来源及操作者。
- 自动保存仅在内容变化并停止输入后触发；保存中、已保存、冲突、离线和失败状态必须明确显示。
- `VersionDiff` 比较两个真实修订或草稿/正式快照，区分新增、删除和修改字段。

## 并发与恢复

- 版本不匹配返回 `version_conflict`，客户端不得静默重试覆盖；必须重新加载并由用户合并。
- 恢复历史调用治理 RPC，锁定当前版本并产生版本号更高的新草稿；正式内容不变，旧审批和排期失效。
- 空内容、非法 JSON、超大负载和网络超时均不得显示“已保存”。

## 验收流程

1. 连续编辑后确认只产生合理次数的自动保存，刷新页面恢复最后草稿。
2. 两个浏览器同时打开同页，A 保存后 B 保存必须出现版本冲突且 A 内容不丢失。
3. 对标题、正文、数组和删除字段查看差异，核对原值与新值。
4. 恢复历史版本后确认产生新修订、正式页未变、旧审批/排期失效。
5. 模拟离线、500、超时和非法数据，确认状态真实且允许安全重试。

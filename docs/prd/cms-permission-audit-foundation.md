# CMS 权限审计基础 PRD 与验收

## 目标

为后台所有读写动作建立七角色最小权限模型和不可由浏览器伪造的审计证据。角色包括超级管理员、编辑、SEO、翻译、销售、审核者和只读用户；权限判断统一由数据库函数执行，前端隐藏按钮不能替代服务端授权。

## 数据与规则

- `cms_admins` 记录角色、启停状态；停用账户立即失去后台能力，最后一名启用中的超级管理员不得被停用或降级。
- `cms_current_role()` 和 `cms_can(capability)` 是数据库权限事实源；所有业务 RPC 再次校验能力。
- `cms_audit_logs` 记录操作者、动作、资源、时间及非敏感元数据；普通角色不能新增、修改或删除审计日志。
- service-role 只用于自有服务器执行器，不进入浏览器，不以 UI 角色模拟。

## 失败与安全

- 未登录、停用、能力不足、浏览器直接写受保护表均拒绝。
- 审计元数据不得包含密码、令牌、私钥、客户正文或完整第三方响应。
- 角色变更、审批、发布、恢复及服务任务均需保留资源 ID 与版本证据。

## 验收流程

1. 用七类真实测试账户逐项验证菜单可见性、RPC 成功/拒绝和 RLS 直写拒绝。
2. 停用账户后刷新会话，确认读写立即失败；尝试停用最后一名超级管理员必须失败。
3. 执行编辑、提交、审批、发布、恢复，核对审计操作者、资源、动作和时间。
4. 尝试直接插入、更新和删除审计日志，确认均被拒绝。
5. 导出审计样本，确认无令牌、私钥或客户敏感正文。

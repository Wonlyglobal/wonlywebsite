# CMS Webhook 与自动化 PRD

## 目标与模型

为发布、询盘、审核、翻译、发布环境、质量、接口和备份事件提供可靠的服务器Webhook。使用事务型发件箱：业务事务产生事件记录，独立自有服务器领取、签名、发送并记录结果，避免页面请求直接调用第三方。

- CMS仅保存端点引用，如`crm_pipeline`；实际URL和HMAC密钥只存在服务器`CMS_WEBHOOK_ENDPOINTS`。
- 固定事件白名单，禁止管理员提交任意事件、URL、请求头或代码。
- 询盘事件负载只含ID、来源和语言，不含姓名、邮箱、电话或留言。
- 签名为`HMAC-SHA256(secret, timestamp + "." + rawBody)`，请求头包含时间戳、签名和唯一delivery ID。
- 失败按30秒指数退避，最多1小时，达到配置次数后终止；领取使用`FOR UPDATE SKIP LOCKED`支持多worker且避免重复领取。

## 验收流程

1. 非超级管理员不能查看或修改自动化；非法端点引用、事件或尝试次数被数据库拒绝。
2. 发布与询盘提交事务成功时各生成一条outbox，事务回滚时不生成。
3. 接收端用原始请求体重算签名并校验时间戳和delivery ID。
4. 2xx标记delivered；4xx/5xx、超时和DNS失败进入重试，达到上限标记failed。
5. 多worker并发领取同一批任务时每条仅被一个worker处理。
6. 未配置端点引用时记录`endpoint_not_configured`，不尝试任意网络地址。
7. 测试事件使用相同队列和签名链路，不能绕过服务端。
8. 真实CRM测试端点验证一次且仅一次业务处理，并以delivery ID实现接收端幂等。

数据库迁移、worker守护进程、真实签名接收端和失败重试演练完成前不得标记上线。

# CMS 插件与接口健康监控 PRD

## 目标

用自有服务器真实探测替代静态“已连接”标签，覆盖DeepSeek、GA4、GSC、Supabase、CRM询盘同步、官网邮件表单和部署服务。CMS与数据库只保存密钥环境变量名称，不保存或返回密钥值。

## 数据契约与安全

- 集成状态：未配置、未知、正常、降级、失败。
- 每次检查保存请求人、时间、HTTP状态、耗时、安全错误摘要和不含路径/query/凭据的证据。
- 浏览器只发送数据库生成的 `check_id`；自有服务验证JWT、超级管理员、任务归属和pending状态后，从服务器环境变量解析固定目标。
- `CMS_INTEGRATION_HEALTH_TARGETS`只在服务器保存，格式按集成键配置URL、方法、请求头和超时；数据库及浏览器不可读取。
- 没有目标配置时必须记录“未配置”，不能显示正常；非2xx按4xx降级、5xx/网络失败分类失败。

## 验收流程

1. 七项集成初始均为未配置/未知，不出现虚假已连接。
2. 非超级管理员无法创建检查任务，服务端也拒绝伪造请求。
3. 分别验证2xx、4xx、5xx、超时、DNS失败和未配置目标，状态与证据准确。
4. 证据中只含主机名、方法、HTTP码和耗时，不含密钥、完整URL查询或响应正文。
5. 重复检查五分钟内返回 `check_already_running`。
6. 浏览器展示最近检查时间、耗时、错误及证据；桌面与390px可用。
7. DeepSeek、Google、CRM、表单及部署服务分别用其真实健康/只读接口验收。

数据库迁移、自有服务部署和全部真实接口检查完成前不得标记上线。

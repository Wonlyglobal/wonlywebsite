# CMS 发布审批 PRD 与验收

## 目标

建立草稿、预览、提交、异人审核、批准和发布的受控链路。正式内容只来自审核时绑定的不可变快照，避免批准后又修改草稿再直接上线。

## 状态与权限

- 编辑者保存草稿；具备提交能力的角色创建 `cms_review_requests`，绑定页面 ID、请求版本、快照及哈希。
- 审核者批准或退回；申请人与审核人必须不同，审核意见和时间进入审计。
- 发布者只可发布状态为 approved 且页面版本、快照哈希仍匹配的请求。
- 预览链接短期有效、可撤销，仅呈现指定快照，不赋予后台权限。

## 失效规则

- 提交后再次编辑、恢复历史、应用模板或批量修改 SEO 时，旧审批和关联排期失效。
- 自审、重复审批、重复发布、过期预览、版本不匹配和快照不匹配均拒绝。
- 发布失败不得更新 `published_content` 或显示成功。

## 验收流程

1. Editor 保存并生成预览，核对预览与草稿一致、正式页不变。
2. A 提交后尝试自审必须失败；B 退回并填写意见，A 可修改重提。
3. B 批准后修改草稿，发布必须因快照失效而失败。
4. 重新提交并由异人批准、Publisher 发布，核对正式内容、版本、操作者与审计。
5. 测试过期/撤销预览、重复操作、网络失败和无权限角色。

# CMS 备份恢复 PRD

## 目标与安全边界

通过自有服务器执行staging/production数据库私有备份及受控恢复。浏览器只能提交数据库生成的任务ID，不能提供数据库URL、存储路径或命令。备份对象位于非公开 `cms-backups` 桶，不在CMS提供下载。

## 流程

- 备份：超级管理员申请，服务端使用固定环境连接运行custom格式`pg_dump`，计算SHA-256后上传私有桶并回写字节数与摘要。
- 恢复：只能选择状态completed且含SHA-256的备份；申请后等待另一名超级管理员或审核人审批，申请人不得自审。
- 服务端下载后重新计算摘要；不一致立即失败。恢复前自动备份目标数据库并保存安全副本，然后才运行固定参数的`pg_restore`。
- 服务端调用子进程不使用shell，错误会截断并清理数据库连接信息；临时目录最终强制删除。

## 验收流程

1. 普通角色不能创建备份/恢复；恢复申请人不能自审。
2. 未完成、无摘要或被篡改备份不能恢复。
3. staging备份完成后私有桶对象存在，大小和SHA-256与本地流一致，匿名不可读取。
4. 恢复前安全副本成功上传；安全副本失败时不得开始恢复。
5. 先在staging恢复并核对表数量、关键CMS页面、角色和最新审计记录。
6. 人为破坏摘要后返回`backup_checksum_mismatch`且目标数据库不变化。
7. 生产恢复必须重复异人审批与恢复后全站/CMS回归，不允许自动跳过staging验证。

数据库迁移、服务器pg工具和私有桶权限、staging演练及生产恢复演练证据齐全前不得标记上线。
